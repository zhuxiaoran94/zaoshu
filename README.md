# Mock造数工具

面向测试人员的浏览器端测试数据工作台。内置 120+ 字段生成类型和用户、电商、金融、游戏、社区、物流、测试通用七类场景，无需上传任何数据即可生成多表关联测试数据。

当前版本：**6.2.0 响应裁剪与关联展开版**。网站没有匿名写入接口，访客的数据与配置仅保存在各自浏览器中。

## 功能

- 可视化字段配置、固定随机种子、唯一性和跨表外键
- 随机、真实分布、边界、异常、Pairwise 组合模式
- 异常数据注入与 `_mock_meta` 预期结果标记
- 数据质量检查、覆盖报告和业务状态链
- JSON、JSONL、CSV、TSV、XLSX、MySQL、PostgreSQL、SQLite 导出
- 一键导出可直接接入前端与测试项目的 MSW v2 Mock API 包，包含固定数据、浏览器/Node 启动器和 OpenAPI 契约
- Postman 数据、TypeScript Fixture 和 Markdown 报告导出
- 可选本地自定义数据池，所有配置保存在浏览器
- 项目配置安全备份、恢复内置模板和清除本地数据
- CSV/XLSX 公式注入防护、SQL 标识符转义和严格配置校验
- 数据表新增、复制、重命名、排序、删除及关系视图
- 项目结构修改支持 30 步撤销和重做
- 生成前即时诊断循环依赖、失效引用、名称冲突、范围错误和唯一值容量
- 阻断问题不会启动生成，诊断结果支持点击定位到对应表和字段
- 可视化配置 AND/OR 条件字段，支持 7 种比较操作与不满足时置空或移除
- 电商模板内置“支付成功才生成支付时间”的可运行条件示例
- Pairwise 支持 2–8 个维度、非法组合排除、关键组合强制包含和 100% 合法参数对覆盖审计
- Pairwise 用例可直接导出 JSON、CSV 和 Postman Runner 数据
- 状态链支持实体数量、终止状态、停留时长和状态倒退/跳过/重复三类异常
- 状态事件包含稳定 Trace ID、事件序号、停留时长和异常标记，可导出 JSON/CSV
- 首次完整打开后支持 PWA 安装和离线使用，断网仍可生成、预览及读取本地项目
- 新版本静默下载后由用户确认刷新，编辑中的项目不会突然丢失
- 最多保存 20 个命名项目快照，一键恢复任意 Schema 版本
- 快照可与当前项目进行项目、数据表、字段三级差异比较
- 结果表支持按字段锁定并重新生成单行，主键自动保持，外键继续来自有效父表
- 手工编辑会按字段类型解析；编辑、删行或重生成后质量报告立即重算
- 字段统计展示缺失率、空值率、唯一率、范围和高频值 Top 3
- 可选导入 OpenAPI 3 JSON 或普通 JSON 样例，先预览再确认建立项目
- 自动推断表、字段类型、格式生成器、枚举、范围、必填性及常见 ID 外键关系
- 导出支持 JSON/JSONL/CSV/TSV/YAML/XML/XLSX、三种 SQL 与六类测试 Fixture
- 每次导出均为 ZIP，内附 Manifest、SHA-256、种子、Schema 版本和异常比例
- 完整交付包一次包含全量 JSON、逐表 CSV、三种 SQL 与覆盖报告
- Faker 生成引擎和 Web Worker 按需加载；XLSX 使用内部只写实现，不引入有已知高危漏洞的工作簿解析器
- 构建内置 450 KB 首屏 JS 性能预算，超出即阻止版本发布
- 支持 MySQL、PostgreSQL、SQLite `CREATE TABLE` DDL 导入，推断列、主键、唯一约束和外键
- DDL 仅作文本结构解析，忽略 DROP/INSERT 等语句，不连接或执行数据库操作
- 真实分布模式支持均匀、正态、长尾、热点、递增和递减六种可复现分布
- 枚举与自定义数据池支持任意非负权重，并在生成前检查数量不匹配和全零配置
- 数字与日期字段均可应用分布；内置用户、电商模板预设会员、状态、金额、库存和时间分布
- 字段设计器提供分布形态预览与中心值配置，覆盖报告显示已应用的真实分布字段数
- 覆盖报告精确审计枚举候选值、NULL、字段缺失和显式数值边界，不再使用估算百分比
- 每个未覆盖项可点击定位到字段，并可一键追加最少数量的覆盖数据
- 覆盖补数自动生成唯一主键、选择有效外键、重算公式，并同步期望条数与质量报告
- Markdown 覆盖报告同步列出未覆盖项，便于直接放入测试报告和项目 README
- 支持粘贴或读取 `.ts` / `.tsx` 中的对象 `interface` 与 `type`，无需先转换 OpenAPI
- 自动推断数字、布尔、日期、数组、嵌套对象、可选字段、可空字段和字面量联合枚举
- 类型名引用和 `userId` 等 ID 字段可自动建立多表外键，无法识别的成员会明确告警
- TypeScript 仅按文本静态解析，不编译、不导入模块、不运行装饰器或任何输入表达式
- 字段列表支持进入批量模式，配合搜索结果全选、取消全选和逐项选择
- 可一次设置多个字段的空值率、缺失率、异常率和真实分布，适合治理导入的大型 Schema
- 支持批量删除字段；自动保护最后一个字段和仍被外键引用的目标字段
- 整组批量修改只产生一个撤销记录，误操作可以一步恢复
- 自动记录最近 10 次成功生成的项目配置、种子、模式、条数、耗时和质量摘要
- 可从运行历史一键恢复当时的 Schema 并重新生成，稳定复现测试数据与缺陷现场
- 历史记录支持逐条删除，并随“清除本地数据”一起移除
- 运行历史只保存配置和小型摘要，不保存生成结果，避免大量测试数据占满浏览器
- OpenAPI 3 支持 JSON 与 YAML 两种格式，可粘贴或读取 `.yaml` / `.yml` 文件
- YAML 解析器仅在发起 Schema 分析时按需加载，不增加首页核心 JavaScript 体积
- 严格拒绝重复键、无法解析的文档、未知自定义标签及超过上限的别名展开
- YAML 与 JSON 共享字段、枚举、范围、必填性、格式生成器和多表外键推断流程
- 支持 OpenAPI 文档内部 `#/components/schemas/*` 引用和 `allOf` 继承合并
- 对象 `$ref` 在目标模型存在主键时自动建立可生成外键，数组 `$ref` 保留为嵌套数组并给出提示
- 自动检测缺失引用、循环引用和超过 20 层的引用展开，拒绝 URL、文件路径等外部 `$ref`
- 对象与数组固定值以真实 JSON 对象/数组生成，不再导出为字符串形式的 `{}` / `[]`
- 结果表格支持字段显示/隐藏、全部显示与全部隐藏，JSON 预览同步遵循可见列
- 点击字段名可在升序、降序和原始顺序之间切换，正确处理数字、日期、文本与空值
- 搜索、只看异常、排序和隐藏列可以组合使用，并显示当前匹配数量
- “当前视图”可把全部匹配行和可见列直接导出 CSV，不受页面前 100 条预览限制
- 视图变换不修改底层数据，编辑、删行和单行重生成仍精确对应原始记录
- 质量检查覆盖数据量、必填、类型、唯一性、外键、数值范围、文本长度和枚举合法性
- 每项失败记录真实问题数量、所属表、字段和最多前 200 个问题行号
- 点击失败或预期异常检查可自动切换表与字段，并只显示对应问题行
- 问题行视图提供“查看全部数据”恢复入口，可继续编辑、删除或重生成问题记录
- 条件字段、边界模式和异常模式会按语义区分通过、预期异常与真实失败，减少误报
- 计算字段支持括号、四则运算、取模、比较、逻辑运算、三元条件和短路求值
- 白名单函数包含 `round`、`min/max`、`length`、`concat`、`coalesce`、`if`、大小写和日期加减/差值
- 多个计算字段按依赖顺序自动计算，生成前检测字段缺失、语法错误、自引用和循环依赖
- 公式由自研 tokenizer、parser 和 AST 解释执行，不使用 `eval`、`Function`、属性访问或任意函数调用
- 项目可复制为隐私分享链接，只携带通过校验的 Schema 与种子，不包含生成结果、数据池、快照或历史
- 分享内容存放在 URL `#fragment` 中，不会随 HTTP 请求发送给 Cloudflare；打开后立即移除并创建独立本地副本
- 分享链接最大 60,000 字符，超限项目改用 `.mock.json` 配置文件，损坏或伪造的分享内容会被拒绝
- GitHub Actions 对每次 push/PR 运行锁定依赖安装、全部测试、生产构建、Cloudflare/PWA 产物与首屏体积检查
- CI 和 Dependabot 阻断新增高危生产依赖漏洞，CODEOWNERS、PR 模板和贡献规则要求维护者审查公开改动
- Excel 多表导出由受控 Office Open XML 写入器完成，只生成工作簿、不解析输入文件，并保留公式注入防护
- CLI 可直接使用七套内置模板或网页导出的 `.mock.json`，覆盖种子、模式、每表数量和 20 种导出格式
- CLI 支持 dry-run、机器 JSON 摘要、质量失败退出码和安全拒绝覆盖，适合 CI 测试准备与产物留档
- `⌘/Ctrl + K` 命令中心统一搜索生成、导出、项目、Schema、数据池、模式、模板和结果面板
- 命令中心支持中文/英文关键词、多词过滤、↑↓/Enter/Esc 操作、焦点陷阱与关闭后焦点恢复
- 全局快捷键支持 `⌘/Ctrl + Enter` 生成、`⌘/Ctrl + Shift + E` 导出、`⌘/Ctrl + Shift + P` 项目和撤销/重做
- 手机端只保留命令入口与主生成操作，项目、导出、Schema 等功能收进命令中心，390px 视口无横向溢出
- 命令面板按需加载为约 3.8 KB 独立模块，v4.0 首屏 JavaScript 保持在约 445.8 KiB
- 内置用户身份、中国地址、组织员工、金额交易、审计、接口追踪、分页、文件、设备、软删除 10 套字段套餐
- 应用套餐前预览所有新增字段和同名冲突，默认安全跳过，也可自动追加 `_2` 等后缀
- 整个套餐只产生一次撤销记录，严格保护 200 字段上限、字段名和字段 ID 唯一性
- 数字/布尔自定义枚举会按字段类型生成、校验和分析覆盖缺口，补数时不再发生字符串类型漂移
- 当前项目无需先生成数据即可导出 Schema 契约 ZIP，适合评审、接口联调和纳入代码仓库
- 契约包包含 JSON Schema 2020-12、OpenAPI 3.1、TypeScript 类型、三种数据库 DDL、关系说明和校验 Manifest
- JSON Schema/OpenAPI 保留类型、必填、范围、枚举、格式，以及 Mock 生成器、公式、条件和外键扩展
- MySQL、PostgreSQL、SQLite DDL 按外键依赖顺序建表，并转义表名和字段名
- 每个外键可独立选择种子随机、轮询均匀、热点 80/20 或严格一对一分配，旧项目默认保持随机策略
- 热点策略可调整热点父记录池占比，适合制造缓存穿透、热点账户和数据倾斜场景
- 严格一对一按策略保证唯一绑定并关闭随机留空；父表容量不足或条件规则破坏绑定时生成前直接阻断
- 关系视图按真实依赖顺序展示，并在生成后统计父记录覆盖数、未使用数、引用范围和 Top 1 占比
- 质量检查新增严格一对一重复引用和轮询均衡度审计；配置、分享与 Schema 契约完整保留分配策略
- 数据表可选择一个外键作为基数驱动，直接表达“每个用户 1–3 个订单、每个订单 2–4 条明细”
- 子表数量由父表真实结果逐级计算，支持多级一对多；同一种子下每个父记录的子记录数稳定可复现
- 工具条、侧栏和关系页实时显示动态预计条数，生成前检查单表/项目上限及唯一、空值和条件冲突
- 质量报告逐父记录检查实际子数据数量；单行重生成锁定驱动外键，覆盖补数不会破坏基数关系
- 电商模板开箱即用地启用“用户 → 订单 → 订单明细”两级动态基数，无需手算子表总量
- 字段可按外键从父表回填值，或按父子关系对明细安全求和、计数、取最小值和最大值
- 电商模板自动保证订单金额等于明细成交价乘数量之和、支付金额等于对应订单金额
- 跨表表达式使用既有白名单公式解析器，不执行 JavaScript；多级计算自动排序并检测循环依赖
- 质量报告逐行审计跨表计算结果，手工篡改金额会定位到具体表、字段和数据行
- 异常模式保留定向注入的金额不一致与无效明细，不会被自动重算掩盖或拖垮整批生成
- JSON Schema、OpenAPI、项目配置与关系说明完整保留跨表计算规则
- 每张表可配置最多 20 条业务断言，用安全公式表达“成功必须有时间”“金额必须为正”等跨字段约束
- 断言支持失败和警告两级，逐行检查并定位真实问题；边界/异常模式下规则违例会标为预期异常
- 内置电商支付表预设“成功支付必须有支付时间”，打开模板即可获得可运行示例
- 断言使用同一套无 `eval` 白名单 AST 引擎，仅能读取当前记录字段，语法和字段引用在生成前检查

- 顶部可设置项目时间基准，相同 Schema、种子和基准日期在不同日期、设备与 CI 中仍生成相同业务数据
- 过去/未来日期、最近时间戳、生日、季度、财年、ULID、雪花 ID、订单/流水号和 `{date}` 模板统一使用项目基准
- 状态链事件时间同样跟随项目基准；一键“设为现在”适合临时联调，固定日期适合回归和缺陷复现

- 旧项目未包含时间基准时使用固定兼容值，不依赖运行当天，也不会因升级而无法导入
- Mock API 交付包包含 `db.json`、MSW v2 `handlers.ts`、浏览器/Node 启动器、OpenAPI、路由清单与接入说明

- Mock API 新增不受延迟/故障注入影响的健康检查和整库复位接口，100% 失败场景下仍能确认数据状态并恢复测试基线
- 批量与控制接口完整进入 `routes.json`、OpenAPI、包内 README 和真实 HTTP 回归测试，不存在只有代码没有契约的隐藏能力
- 导出面板可为最多 20 个具体接口单独覆盖延迟、失败率、HTTP 状态码和错误消息，未配置接口继续使用全局网络场景
- 单路由规则只能从当前 Schema 的真实列表、单条、批量和父子路由中选择；路径、方法、数值和消息统一经过白名单归一化
- 命中覆盖规则的响应带 `X-Mock-Route-Override`，OpenAPI 操作带 `x-mock-route-override`，方便联调和回归断言规则确实生效
- CLI 支持重复使用 `--mock-api-route 'METHOD|path|min:max|rate|status|message'`，并在生成前拒绝当前 Schema 中不存在的路由
- 每个业务响应自动返回稳定 `X-Mock-Request-Id`，便于把测试失败与 Mock 请求轨迹对应起来
- 本地控制接口可查询最近 500 条请求，支持方法、状态码和数量筛选，并可只清空轨迹而不重置业务数据
- 请求轨迹只保存方法、pathname、状态、延迟、故障标记和命中规则；不会记录 query、body、Authorization、Cookie 或其他 header
- `requestLog` 同时从浏览器和 Node 入口导出，测试代码无需 HTTP 查询也能直接断言请求序列
- 导出的 Mock API 可用命名场景快照保存当前整库、执行破坏性测试后再精确恢复，适合退款、级联删除和异常状态回归
- 快照只存在于使用者本地内存，最多 10 个且单个不超过 5 MiB；名称严格白名单，支持同名覆盖、列表、单删与全清
- `resetMockData()` 会清掉业务修改、请求轨迹、网络序列和全部快照，避免用例间状态泄漏；快照控制面不受故障注入影响
- Mock API 的统一 `/_batch` 路由支持原子批量新增、修改和删除，每批 1–1,000 条，失败项带从 0 开始的 `index`
- 批量修改使用 `{ id, changes }` 且禁止改主键；任一记录不存在、ID 重复或外键无效都会回滚本批已经执行的修改
- 批量删除预检全部 ID 与引用关系后再落库；`restrict` 模式整批拒绝被引用记录，`cascade` 模式递归删除后代并返回级联数量
- Mock API 新增受限 JSON 跨表事务，一次可按顺序 `create/update/delete` 多张表，任一步失败就恢复整个数据库
- 事务支持 `$alias.field` 引用前序动作结果，可先新建用户、再用生成的用户 ID 创建订单，无需在测试代码里拆成多次请求
- 事务最多 100 步、1 MiB、10 层值嵌套；只接受 Schema 表和白名单动作字段，不执行 JavaScript、不访问外部 URL
- Mock API 可选开启严格 Schema 校验，覆盖未知字段、类型、必填、空值、枚举、数值范围、文本长度和主键不可修改
- 校验失败统一返回 HTTP 422 与 `field/rule`，批量和事务额外返回 `index`，可直接定位自动化测试的失败输入
- 严格模式默认关闭以兼容宽松 Mock；网页导出可勾选，CLI 可用 `--mock-api-strict-schema` 显式开启
- Mock API 自动执行 Schema 中除主键外的唯一字段约束，手机号、邮箱、SKU、订单号、流水号等重复时返回 409
- 唯一冲突返回 `field` 与 `rule: unique`；单条、批量、跨表事务共用规则，不依赖严格 Schema 开关
- 批量或事务在后续动作撞唯一值时会恢复此前所有变更，避免“前半批成功、后半批失败”的污染数据
- 单条新增、批量新增和跨表事务支持 `Idempotency-Key`，网络超时重试或并发重复请求只执行一次并稳定重放原响应
- 幂等键限制为 1–80 位安全字符；同键异参返回 409，超过 1 MiB 的签名输入返回 413，响应头区分首次存储与缓存重放
- 幂等缓存仅在使用者本地内存保存最近 100 项且总计不超过 10 MiB；可单独清空，整库复位也会清空，不记录键值或请求体
- OpenAPI、路由清单、包内 README、健康状态与真实 HTTP 自测完整公开幂等能力，模拟网络失败不缓存以支持真实重试流程
- Mock API 单条 GET/POST/PATCH/DELETE 返回强 `ETag`，内容变化时版本指纹稳定变化，不需要在业务 Schema 中添加版本字段
- GET 支持 `If-None-Match` 与 304；PATCH/DELETE 支持 `If-Match`，过期页面或并发任务写入时返回 412 和最新 ETag
- 原子批量修改/删除可为每项携带 `ifMatch`；跨表事务 update/delete 动作也支持版本前置条件，任一过期会完整回滚
- ETag/条件头长度受限且不会写入请求轨迹；OpenAPI 和独立工程自测覆盖 200/304/412、批量与事务回滚
- Mock API 列表字段支持 `eq/ne/gt/gte/lt/lte/contains/starts/ends/in/isnull` 11 种操作符，多个条件可直接按 AND 组合
- `_sort` 支持最多 5 个字段，字段名前加 `-` 表示降序；数字按数值、日期按时间、文本按字典顺序稳定比较
- 查询限制为最多 50 个参数、单值 1,000 字符、`in` 50 项和 5 个排序字段，超限或非法操作符明确返回 400
- 高级查询能力与安全上限写入 OpenAPI 扩展、包内 README 和独立 HTTP 测试，未知业务字段继续兼容性忽略
- 可用受限 JSON 声明某条业务接口至少/至多调用几次以及允许哪些响应状态码，直接检查漏调、重复提交和错误重试
- 调用预期只接受当前 Schema 实际启用的业务路由，最多 100 条，次数上限 10,000、状态码最多 20 个，不执行代码也不读取请求体
- 验收结果区分 `pending/passed/failed`，提供逐条计数与状态码分布；全部满足返回 200，否则 `/verify` 返回 409
- 可保留规则单独重置计数，也可单删/全清；整库复位同步清空规则，OpenAPI、路由清单和独立 HTTP 测试完整覆盖
- 列表支持 `_cursor=start` 启动游标分页，后续使用 `X-Next-Cursor`，响应 meta 提供 `nextCursor/hasMore/limit/total`
- 游标与资源、筛选和排序条件绑定并由进程随机密钥签名，篡改、跨接口或跨查询复用会返回 400
- 游标排序自动追加主键作为稳定消歧，翻页期间新增更早数据不会让已读记录重复，同时保留原 `_page` 页码分页
- 游标最长 4,200 字符且不能与 `_page` 混用；OpenAPI 同时描述两种 meta，独立 HTTP 测试覆盖增量写入和安全拒绝
- 列表和单条 GET 支持 `_fields=id,status` 只返回所需字段，减少大型 Schema 的联调响应体
- 子表可用 `_expand=userId` 将父记录展开到 `userId_expanded`，无需前端再发一次查询；只展开当前 Schema 的直接外键
- `_fields` 最多 50 项、`_expand` 最多 5 项且只展开一层，未知字段或关系返回 400，避免递归放大与越权字段访问
- 响应裁剪与关联展开会绑定游标查询；ETag 仍基于完整底层记录，换一组展示字段不会绕过并发更新检测

## CLI / CI 使用

无需准备数据或配置，直接用内置电商模板生成完整交付包：

```bash
npm run mock -- --template commerce --seed 42 --format bundle --output artifacts/commerce.zip
```

固定时间基准，确保本地与 CI 的相对日期完全一致：

```bash
npm run mock -- --template commerce --seed 42 --reference-date 2030-01-15 --format bundle --output artifacts/commerce.zip
```

先校验计划，不生成或写入文件：

```bash
npm run --silent mock -- --template testing --count 100 --dry-run --json
```

复用网页“下载配置”得到的 Schema，并输出机器摘要；存在非预期质量失败时让 CI 失败：

```bash
npm run mock -- \
  --config project.mock.json \
  --format xlsx \
  --output artifacts/mock.zip \
  --summary artifacts/mock-summary.json \
  --fail-on-quality
```

运行 `npm run mock -- --help` 查看所有模式与格式，`--list-templates` 查看七套内置模板。CLI 默认不联网、不执行输入代码、不覆盖已有文件；只有明确传入 `--force` 才允许覆盖指定输出。

不生成测试数据，直接从内置模板或项目配置导出契约：

```bash
npm run mock -- --template commerce --format schema --output artifacts/commerce-schema.zip
```

生成可直接放入前端/Vitest 项目的 MSW v2 Mock API：

```bash
npm run mock -- --template commerce --seed 42 --format mock-api --output artifacts/commerce-mock-api.zip
```

解压导出包后可作为独立工程自检：

```bash
cd mock-api
npm install
npm run typecheck
npm test
```

模拟 120–480 ms 延迟、15% 的 HTTP 429，并使用带分页元信息的响应：

```bash
npm run mock -- --template commerce --seed 42 --format mock-api \
  --mock-api-latency 120:480 \
  --mock-api-failure-rate 15 \
  --mock-api-failure-status 429 \
  --mock-api-envelope data-meta \
  --output artifacts/commerce-network-mock.zip
```

需要在测试清理时级联删除整条业务链：

```bash
npm run mock -- --template commerce --format mock-api \
  --mock-api-delete cascade \
  --output artifacts/commerce-cascade-mock.zip
```

默认使用 `restrict`；也可用 `--mock-api-no-fk-check` 或 `--mock-api-no-nested` 关闭对应能力。

只让支付创建接口稳定模拟 30% 渠道限流，其他路由保持全局配置：

```bash
npm run mock -- --template commerce --format mock-api \
  --mock-api-route 'POST|/api/payments|120:500|30|429|支付渠道限流' \
  --output artifacts/commerce-payment-failure.zip
```

`--mock-api-route` 可重复使用；格式为 `METHOD|/api/path|min:max|rate|status|message`。路径必须属于当前 Schema，控制接口不能被覆盖。

导出 ZIP 已包含独立工程的精确依赖；解压后运行 `npm install` 即可。浏览器入口调用 `startMockApi()`，Node/Vitest 使用导出的 `server`；详细路由与接入代码在包内 `mock-api/README.md`。

## Cloudflare Pages

- 构建命令：`npm run build`
- 输出目录：`dist`
- Node.js：18 或更高版本

项目没有服务端接口，所有造数、检查与导出均在浏览器本地完成。

### 为什么公开部署不容易被别人搞坏

- 站点是 Cloudflare Pages 静态文件，没有数据库和公共写入 API。
- “Mock API”是下载到使用者项目中的本地拦截代码，不在 Cloudflare 站点托管可写数据。
- 用户配置、业务字典和生成结果均不上传，访客之间互不影响。
- 分享链接只携带 Schema 与种子并使用 URL fragment；它不是加密或访问控制，持有链接的人可以查看规则并编辑自己的副本。
- 导入文件有 1 MB 体积限制，并校验表数、字段数、行数和字段格式。
- Schema 导入只解析当前文档内部 `$ref`、不发送网络请求；TypeScript、SQL、JSON 和 YAML 输入均不会执行。
- CSP、禁止 iframe 嵌入、权限策略和跨源资源策略由 `_headers` 下发。
- Service Worker 仅处理同源 GET 静态资源，不缓存第三方响应或任何写请求。
- 大任务进入 Web Worker，单项目总生成量限制为 200,000 条，可主动取消。
- 生产依赖的高危漏洞由 CI 阻断；Cloudflare 安全响应头与 SPA 回退规则在每次构建中自动检查。

公开仓库不能阻止别人阅读或复制前端源码，但访客不能通过网站修改仓库、部署文件或其他用户的数据。

公开贡献说明见 [CONTRIBUTING.md](./CONTRIBUTING.md)，漏洞请按 [SECURITY.md](./SECURITY.md) 私下报告，不要在 Issue 中公开真实数据或利用细节。
